# Apple deployment playbook

Follow [README.md](README.md), fill [APP.md](APP.md), and checkpoint [STATE.md](STATE.md). This is an operating procedure, not evidence that the account or app has been checked. Reverify current official requirements against the project's actual tools before execution.

## 1. Account and access

- Resolve the real seller/team. The owner enrolls the individual or eligible organization, completes identity/payment, enables Apple Account 2FA, and accepts current agreements. Paid apps/IAP also need applicable paid-sales agreements, tax and banking setup. Use existing active enrollment rather than repeating onboarding. [Enrollment](https://developer.apple.com/programs/enroll/), [agreements](https://developer.apple.com/help/app-store-connect/manage-agreements/sign-and-update-agreements/).
- Verify effective App Store Connect role/app scope separately from signing access. Developer can upload builds; App Manager can perform app/review/release operations. Inviting an App Store Connect user to an individually enrolled owner does not grant Developer Program signing-team membership. [Roles](https://developer.apple.com/help/account/access/roles), [upload access](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds).
- Select an existing supported route: Xcode account, team API key, or individual API key with independent signing access. Individual keys cannot access provisioning endpoints; team keys span all apps and need the right role. An API `.p8` is not a distribution-signing private key. Keep secret files outside the repository. [API key types](https://developer.apple.com/documentation/AppStoreConnectAPI/creating-api-keys-for-app-store-connect-api).
- Use the required [Cua Driver setup](CUA-DRIVER.md) for portal and native Xcode GUI work; verify installation, OS permissions and window access first. The owner handles password/MFA, identity/payment and agreement acceptance. Resolve factual selections from evidence, asking only about unresolved facts; apply and read back the owner's answers. Credential presence is insufficient; verify the selected account/team with read-only access.

## 2. App identity and distribution signing

- Find/reuse the exact bundle ID and App Store Connect record. Register missing explicit identifiers and actual capabilities, including extensions. Create a missing app through the Console when the API client does not support creation; do not invent an API endpoint. Record the Apple app ID, SKU and locale. [Create an app](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-a-new-app).
- Reuse valid certificates/private keys and matching App Store profiles. Ensure every signed target's bundle/team/entitlements match. Manual App Store profile creation requires Account Holder/Admin. A development or ad-hoc profile cannot establish distribution readiness. [App Store profiles](https://developer.apple.com/help/account/provisioning-profiles/create-an-app-store-provisioning-profile).
- Respect `DEVELOPER_DIR`. Inspect installed `xcodebuild -help`; archive Release for `generic/platform=iOS`, then export with `method=app-store-connect`, `destination=export`, the verified team and appropriate signing/profile mapping. The actual project/workspace, scheme and commands belong in APP.md.
- `-allowProvisioningUpdates` may create/update remote signing resources. Use it within the authorized provisioning task, with an Xcode account or supported team-key authentication arguments; do not use it as a read-only diagnostic. Include extensions in validation.
- Verify the exact IPA's bundle/version/build, device platform, signatures, entitlements, profile kind/team/expiry, current SDK acceptance, and SHA-256. Keep the archive and symbols. A simulator build or development IPA is not the release artifact. If a local preflight helper exists, retain its report while completing its unknown/live checks separately.

## 3. Listing and declarations

Follow [APPLE-SECTIONS.md](APPLE-SECTIONS.md): open and read every actual app section, including conditional questionnaires, then select the best evidence-supported answers automatically and inform the user of the choices and reasons. Ask only about unresolved facts, apply the user's response, and reopen/read back the saved answer. Keep the coverage and decision journal at `release-output/apple-sections.md`; missing access or unanswered fields remain visible. Use actual product facts and real media from `release-output/`. [Submission requirements](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app/).

Validate the actual built app icon with [ICONS.md](ICONS.md), preserving the project's asset-catalog or Icon Composer route. Finish any icon integration before the final archive/export.

Validate screenshots and optional previews for every supported display family/locale against current specifications. Record the expected files, order and hashes before upload. Preserve valid existing media and unaffected locales. [Media specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications).

## 4. Upload and reconcile

Track these independent results in STATE.md; continue available work within existing authorization when another component is blocked:

1. **Binary transfer.** Upload the exact distribution IPA using Xcode, Transporter, or an implemented supported delivery client. Record its SHA-256 and actual receipt/upload ID. A local archive/export is not a transfer receipt. [Upload routes](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds).
2. **Binary processing and selection.** Poll the exact app/platform/version/build until accepted or failed, preserving Apple's diagnostics. Then select that accepted build on the intended editable draft version and read back its build relationship. Processing acceptance alone does not establish this association. Reconcile uncertain outcomes before retrying or changing the build number. [Processing states](https://developer.apple.com/help/app-store-connect/reference/app-uploads/build-upload-statuses).
3. **Screenshots and other requested media.** Complete transfer/commit and processing, then verify placements and order on the intended version localization for every requested device group. With modern Asset Library, a processed library image/video must also receive a placement on that version: use Product Page Information or Media Manager to add it, or the supported placement API. Read back the version's ordered placements, or reopen Media Manager when using Console, and confirm the expected images and counts; library creation alone is incomplete. Record asset and placement IDs with source hashes. Discover current group/specification identifiers rather than guessing from diagonal screen labels. [Console asset management](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-your-app-store-assets), [placement API](https://developer.apple.com/documentation/appstoreconnectapi/placing-assets-on-your-app-store-surfaces).
4. **Public copy and declarations.** Complete the [section review](APPLE-SECTIONS.md), save only the intended factual fields/locales and read their exact values back from the selected draft or relevant app-level section. Track unresolved declarations separately. A local Markdown listing or a successful media command does not prove copy was saved. Preserve review/publication boundaries for fields that can affect live metadata.

If an existing client requires the deprecated screenshot-set API, use that compatibility route explicitly only while Apple still supports it. Create/reuse the set under the exact version localization/display type, reserve and transfer each screenshot, commit, poll processing, then read back the ordered set and verify its placement in Console. Record why this route was used; do not silently switch after a failed modern upload or duplicate assets across both routes. [Legacy asset protocol](https://developer.apple.com/documentation/appstoreconnectapi/uploading-assets-to-app-store-connect), [asset-library migration context](https://developer.apple.com/documentation/appstoreconnectapi/understanding-the-app-asset-library).

`upload_draft` remains incomplete until all requested binary, association, screenshot/media and copy results are verified, with no review submission. Missing or rejected screenshots remain a visible incomplete component even after a successful build upload. A capture failure does not prevent uploading an already valid binary; missing distribution signing does not prevent authorized media/copy work when account access permits it. For `test`, separately verify availability to the intended TestFlight audience; external testing has its own requirements.

### Optional bundled Apple helper

Use `apple-upload.mjs` with an existing Node.js 18+ runtime; it uses built-in modules. Read `node deploy/apple-upload.mjs --help` and use the actual app facts, not another app's defaults. The helper needs a **team API key** through `ASC_KEY_ID`, `ASC_ISSUER_ID` and `ASC_KEY_PATH` (or an existing default key file at `~/.appstoreconnect/private_keys/AuthKey_<id>.p8`). Keep values outside committed files and logs. It does not use a browser/Xcode login or individual API key; reuse native Xcode/Transporter and Console routes when those are the available authorized access. Do not create new credentials or install tools merely to use this optional helper.

Start with a local-only plan, replacing placeholders from APP.md:

```sh
node deploy/apple-upload.mjs plan --release-output release-output \
  --app-id APP_ID --bundle-id BUNDLE_ID --version VERSION --build-number BUILD
```

Reuse those identity flags with `screenshots`, `build`, or read-only `status`. `--version` identifies the intended App Store draft. If the IPA's marketing version differs, pass it explicitly as `--binary-version` (for example, draft `1.0` with binary `1.0.0`); do not guess or silently normalize the selection. `screenshots` handles manifest entries of kind `app_store_screenshot` using modern library placements; resolve any ambiguous group with the entry's `asc_placement_group` from Apple's reference data. `--media-mode legacy` explicitly selects compatibility and requires `asc_display_type` on each screenshot entry. Use `--replace` only when replacing unmatched existing screenshots is within the requested change. `build --associate` transfers/verifies the exact build and selects it in the intended draft; without `--associate`, build verification covers processing only. Supply the verified distribution IPA via `--ipa PATH --ipa-sha256 HASH` or the manifest's `distribution_build` entry. Neither command uploads listing copy or previews; complete those through the supported API/Console route and track them separately.

Use separate `--receipt PATH` files for component evidence; the default is `release-output/apple-upload-receipt.json`. Polling is bounded with `--timeout-seconds` and `--poll-seconds`. A `pending_external` result (exit 2) is unfinished processing, not permission to retry blindly or a completed draft. `verified` applies only to that command's requested component; inspect receipt details and fresh remote state. For a pre-existing remote build, `localArtifactSha256` alone does not prove matching remote bytes: link the prior upload evidence or retain that uncertainty when `artifactBytesConfirmed` is false. The helper never submits for review or distributes/releases a build.

## 5. Review and release

- Submit the prepared version only under the existing review instruction. “Add for Review” and “Submit for Review” are distinct transitions; retain the submission ID and observed state. Fix concrete rejection causes rather than repeatedly submitting unchanged inputs. [Review submission](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app/).
- If only review is authorized, use manual release. Automatic or scheduled release can publish after approval and requires release authorization before submission. A schedule means no earlier than that date after approval, not guaranteed approval or an exact launch time. [Release modes](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/select-an-app-store-version-release-option/).
- Under an existing release instruction, perform the required transition after approval without asking again. Verify the correct public version in intended storefronts before reporting released. Persist Apple waits as `pending_external`; local timeout is not remote failure. [Publishing workflow](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/overview-of-publishing-your-app-on-the-app-store/).

Finish with app/build/upload/submission IDs, artifact and metadata revision, actual achieved state, timestamp, and next actor/action in STATE.md. Keep signed URLs, tokens, private keys and reviewer credentials out of logs and commits.
