## ShippyKit deployment

For installed ShippyKit, read the project-local `shippykit` skill and `deploy/RESUME.md` first. Adopt existing APP/STATE, handoffs and release evidence; continue the next unfinished dependency rather than restarting the pipeline. `python3 deploy/shippykit.py status --project .` is read-only. Installation alone does not authorize building, uploading, submission or publication.

Follow `deploy/START.md` once when entering ShippyKit in a chat: notify about an available version and show a concise task menu when the request does not already choose a route. Keep direct tasks moving. Artwork follows `deploy/ASSET-REVISIONS.md` for preserved revisions/directions and website comparisons; marketing locales follow `deploy/LOCALIZATION.md` for natural wording and optional Lingo.dev support.

User-supplied photos, video, logos, audio and references follow `deploy/MEDIA-INPUTS.md`: preserve originals, inspect their intended roles, create requested marketing materials and retain input-to-revision links. Show prepared exports in the website and keep raw uploads private.

For a focused image or store-copy refresh, read `.agents/skills/shippykit-images/SKILL.md` or `.agents/skills/shippykit-store-copy/SKILL.md` (or the corresponding skill in the supplied ShippyKit package) and complete only that scope. Generate requested artwork, preserve real UI in screenshots, update grounded localized copy, refresh the manifest and local preview, and follow existing commit/push instructions. This does not start unrelated setup, platform expansion or deployment; store writes still follow the user's actual authorization.

Cua Driver is the required desktop/browser driver for this workflow. Follow `deploy/CUA-DRIVER.md` for prerequisites, installation permission, OS grants and a verified window readback. Preserve existing installations and keep independent build/phone work moving when GUI setup is blocked.

Versions follow `deploy/VERSIONING.md`: one `MAJOR.MINOR.PATCH` version on every platform, build numbers that only go up, and a `CHANGELOG.md` whose every entry names its evidence (commit, file or URL). Use `python3 deploy/versions.py` for all version changes and entries; never edit version numbers by hand.

The public marketing/support/privacy site and its custom domain follow `deploy/DOMAINS.md`: build or reuse the site and host it on Railway. For the domain, run `python3 deploy/domains.py status --domain <domain>` and do what its `NEXT` line says until it reports done; the helper changes Railway and Squarespace itself. Domain purchases, renewals and sign-ins stay with the owner; store URL changes follow the run's store authorization.

For full ShippyKit runs, phone installation, or store deployment beyond the focused refresh above, read `deploy/README.md` and follow its workflow within the user's requested scope. First discover existing targets/setup and offer the missing mobile platform unless the user has already chosen. After opt-in, check that environment read-only and obtain permission for the concrete installation/port plan before executing it autonomously. Explain missing prerequisites before dependent deployment. Use `deploy/APP.md` for project facts and `deploy/STATE.md` for recorded decisions, permissions, evidence and the next resumable step. Consult the applicable Apple/Google playbook. Follow `deploy/ICONS.md` to reuse or generate and integrate app icons before the final build. During asset preparation, automatically generate the website with `deploy/PREVIEW.md` and `deploy/preview.py`; offer temporary ngrok sharing and start it only after explicit opt-in. Populate routine facts from the project; do not ask the user to complete templates manually. Existing user instructions govern commits, pushes, uploads, review submission, and release.

During full store runs, follow `deploy/APPLE-SECTIONS.md` and/or `deploy/GOOGLE-SECTIONS.md` to read each actual section and conditional form. Select supported answers automatically and inform the user of the choices and evidence. Ask about uncertainty, apply the response and verify the saved value. Preserve the selection journal and unresolved questions across resumes; checking forms does not authorize submission or publication.
